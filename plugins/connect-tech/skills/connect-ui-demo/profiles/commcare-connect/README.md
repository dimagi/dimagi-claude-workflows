# Profile: commcare-connect

Everything a Connect demo re-derived every time, done once: demo settings (no Debug Toolbar, email → console only), a realistic idempotent seed, a server script, and a helper library with verified selectors. A new demo is `flow.mjs` = steps + captions (see `flow.example.mjs`, ~40 lines for a five-step flow).

## Set up a task folder

```bash
REPO=$(git rev-parse --show-toplevel); TASK=$REPO/.ui-demo/<ticket-or-slug>; SKILL=<base directory of this skill>
mkdir -p $TASK/output && cd $TASK
cp $SKILL/runner.mjs $SKILL/render.py $SKILL/profiles/commcare-connect/{connect.mjs,record_settings.py,seed.py,serve.sh,reseed.sh} .
cp $SKILL/profiles/commcare-connect/flow.feature-example.mjs flow.mjs   # signed in off camera (most features); flow.example.mjs when login is the story
chmod +x serve.sh reseed.sh
./serve.sh 8010          # runserver with record_settings, waits for readiness; logs → output/server.log
./reseed.sh              # org + users reset, invites cleared — run before every take
node flow.mjs            # Verify Run
node flow.mjs --record   # Record Pass (headed, 2x)
../venv/bin/python render.py --task .
./serve.sh stop 8010     # cleanup
```

`DEMO_PORT=8022 node flow.mjs` if 8010 is taken (pass the same port to `serve.sh`). `serve.sh`/`reseed.sh` find the repo from their own location (`git rev-parse`); `CONNECT_REPO` overrides it.

## Helpers (`connect.mjs`)

`quickLogin(page,user)` (off-camera, for `preAuth` — the default for features that are not about auth), `login(p,d,user)` (on camera), `fillLogin(p,d,user)` (form already on screen, keeps `?next=`), `switchUser(p,d,user)` (clears cookies first — set `useState:false`), `assertLoggedIn(p)` (also asserts the Debug Toolbar is absent), `openOrgMembers(p,d)`, `inviteMember(p,d,email,role)`, `openAdmin(p,d,'organization/organizationinvite/')`, `pickTomSelect(p,d,'id_countries','Kenya')` (any TomSelect field — countries, primary sectors, year of establishment, work areas), plus `urls`, `sel`, `ORG`, `USERS`, `PASSWORD`.

Add helpers here when a second demo needs the same thing; keep one-off selectors in the flow.

## Gotchas this profile already handles

- `DJANGO_DEBUG=False` env var is ignored (`local.py` hardcodes `DEBUG = True`) → settings module override via PYTHONPATH, zero repo edits.
- Under `DEBUG=False` whitenoise needs `staticfiles/staticfiles.json`; `serve.sh` adds `--insecure` when it is missing.
- allauth bounces unverified emails to a verification page mid-login → the seed marks every `EmailAddress` verified.
- Flows that switch identity (admin → invitee) must not reuse `storageState` → `useState: false`.
- **TomSelect fields resist automation in several stacked ways** → always use `pickTomSelect()`, never hand-roll it. The killer is that `.option:text-is("X")` matches only while typing is *broken*, so a hand-rolled version goes green headless and dies headed. Full table in `reference/troubleshooting.md`.
- A value the seed already selected is **hidden from its own TomSelect dropdown** (Child Health Campaign already has India) → pick a value that is not seeded, or add a second one.
- `reseed.sh` never rotates a password that already matches, so it does not log out live sessions. **Your local DB is shared by everything that runs against it**: if a second recording is running on the same database, a reseed still deletes its invites/newcomer and resets org membership under it — don't reseed while another recording runs.
